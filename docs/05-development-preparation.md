# ATI 开发前准备清单 V0.1

日期：2026-11-11。目标是把已确认的需求和数据约束转成可以开始工程实现的输入；本文件不等同于开发排期，也不授权自动交易。

## 1. 开发目标

首个可开发版本的目标是：在交易日 14:30–14:50 生成最多 5 只非 ST A 股候选，展示市场/板块/个股依据、风险和数据时效，并保存不可变快照；交易仍由用户手动完成。系统以信号后 3 个交易日表现为主要观察，1、5 日为辅助。

第一版必须能区分：

- 数据正常但没有符合条件的候选；
- 数据不足、延迟或来源失败，无法安全判断；
- 当前候选与上一轮相比发生了什么变化；
- 当前规则、数据批次和因子版本是什么。

第一版不包含券商接口、自动下单、自动调权、账户级仓位管理、保证盈利的模型或未经验证的政策情绪总分。

## 2. 已锁定的工程决策

| 决策 | 当前值 |
|---|---|
| 时区 | `Asia/Shanghai` |
| 运行窗口 | 交易日 14:30、14:35、14:40、14:45、14:50 计划发布 |
| 研究范围 | 当前全 A 股代码表，排除 ST/*ST；历史 ST 状态仍需补数据 |
| 主数据源 | Fuyao API |
| 补充数据源 | 东方财富公开分钟/资金端点，仅允许 `SHADOW` 模式起步 |
| 主要评价 | 信号后第 3 个交易日，1/5 日辅助 |
| 候选上限 | 每个发布时点最多 5 只，允许 0 只 |
| 规则变更 | 系统提交提案，用户确认后默认下一交易日生效 |
| 数据快照 | 原始响应、标准化数据、因子结果和候选发布不可覆盖 |
| 配置注入 | API Key 只从环境变量读取，不写入仓库和日志 |
| 基础设施 | 复用已有 VPS；部署方案暂不固化具体云资源 |

## 3. 当前阻塞项与处理方式

| 阻塞项 | 影响 | 允许的准备动作 | 解除条件 |
|---|---|---|---|
| 历史 ST 状态不足 | 不能严格回放“当时排除 ST” | 建立状态字段和阻断逻辑 | 用户 API 或补充源提供生效区间状态 |
| Fuyao 外部分钟/资金接口不可用 | 不能独立回测尾盘微观因子 | 适配器保留 `UNAVAILABLE`，东财影子采集 | 连续测试和授权核验通过 |
| 东方财富分钟历史仅短窗口 | 不能多年回放 14:30–14:50 | 从接入日起保存快照，做前向观察 | 累积足够历史或取得授权历史数据 |
| 政策事件结构化数据不足 | 不能把政策直接作为正式评分因子 | 先保存个股新闻/异动原文，人工确认标签 | 有时间版本、来源和行业传导记录 |
| 板块历史成员未确认 | 历史板块轮动可能有成员偏差 | 记录成员快照版本，当前成员仅用于实时 | API 提供历史有效区间或另有历史源 |
| 盘口和交易状态字段不足 | 不能精确判断排队成交和滑点 | 只做信号参考评价，显示可成交性未知 | 补充盘口/状态字段或明确降级规则 |

阻塞项不妨碍建立数据契约、因子登记、原始快照和前向采集；阻塞项未解除时，不把相关因子标为 `ACTIVE`。

## 5. 建议的工程进入顺序

这是依赖顺序，不是多人任务拆分。

### 阶段 A：适配器和数据落地

- 读取 `.env`，校验时区和配置版本。
- 实现 Fuyao 统一响应解析、请求 ID、业务错误和退避。
- 拉取代码表、交易日历、全市场行情快照并保存原始批次。
- 将名称/代码/交易所/上市日期与快照关联；暂时把 ST 状态标为待核验。
- 建立日线历史初始化方式，优先核验全市场导出权限，不能默认逐只补齐已足够回测。
- 建立东方财富 `SHADOW` 适配器，只保存分钟行情和资金原始行，不进入正式评分。

### 阶段 B：数据质量和因子计算框架

- 先完成数据时间、单位、重复、缺失、覆盖率和公司行为检查。
- 因子计算统一返回原值、变换值、状态、来源批次和缺失原因。
- 先实现 L1 日线基础因子和市场/板块当前部分。
- 因子注册表中的 `SHADOW`、`UNAVAILABLE` 不参与正式候选排序。
- 输出中间因子表，便于逐因子复算和人工抽查。

### 阶段 C：候选快照和复盘

- 实现 14:30–14:50 的计划发布和幂等任务。
- 保存每轮完整候选、未入选原因、数据状态和规则版本。
- 手机端先展示数据状态、市场摘要、候选卡片、变化原因和风险；暂不扩展复杂图表。
- 从接入日开始累计真实尾盘快照，准备前向评价。

### 阶段 D：验证和策略提案

- 先跑 BM 简单动量对照，再比较基础因子组合。
- 以 3 日标签为主，1、5 日辅助；保留入口不确定和数据未解决状态。
- 对新增板块、资金、事件因子做共同样本消融，不把覆盖差异误判为收益改善。
- 形成系统提案，但必须人工确认后才改变正式配置。

## 6. 首轮“可开始开发”的门槛

在开始核心因子编码前，至少确认：

- API Key 能通过环境变量注入；仓库扫描不到密钥。
- Fuyao 基础接口返回字段、时间戳、单位和业务错误已能标准化。
- 全市场快照一次运行能保存原始批次及覆盖报告。
- API 失败、429、空结果、迟到数据与合法零值有不同状态。
- 日线历史可取得目标回测范围，或正式将回测范围缩短并记录。
- ST 历史字段的缺口在 UI 和研究结果中明确显示。
- 东方财富补充端点仅进入影子路径，未绕过数据源状态门控。
- 任一候选能追溯到数据批次、因子版本、策略版本和发布时间。

## 7. 首轮完成标准

首轮基础系统完成时，应能够：

1. 在非交易日不生成有效候选。
2. 在交易日按计划产生 5 个时点快照，重试不重复发布。
3. 全市场快照缺失或过期时明确阻断，而不是沿用旧结果冒充新结果。
4. 输出 0–5 只候选，并显示每只的主要依据、风险和数据时间。
5. 保存每轮候选及未入选原因，能够复现当时的因子结果。
6. 为候选创建 1/3/5 日待评价记录，终点按交易日历推进。
7. 页面和接口明确标记 `ACTIVE`、`SHADOW`、`UNAVAILABLE` 因子。
8. 不产生任何自动交易委托。

## 8. 暂不做的决定

在 API 历史覆盖、前向尾盘样本和因子消融结果不足前，不固定：

- 正式资金流阈值和主力资金权重；
- 政策利好/利空的统一分数；
- HMM 状态或自动调权算法；
- 绝对胜率目标；
- 板块集中度的最终硬上限；
- 自动止盈止损和账户回撤结论；
- 东方财富公开端点的长期生产依赖。

这些项目保留在研究配置中，由后续提案和人工确认决定。
