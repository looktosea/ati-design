# ATI 数据契约与验证规则 V0.2

日期：2026-11-11。API 由用户后续提供；本文定义适配要求和研究口径，不绑定供应商。本版未调用实际行情 API、未运行回测、未验证延迟或策略收益。

## 1. 数据接入原则

一个标准数据契约可以适配多个 API，但每个字段都需要来源、语义、单位和时间说明。切换数据源不能静默改变因子含义。原始响应、标准化结果及修订都保留。

API 支持某种字段，不代表它支持全部市场、盘中时点或历史回放。分别记录沪深主板、创业板、科创板、北交所的覆盖。某源只覆盖沪深时不能宣称已经实现全 A 股筛选。

## 2. 标准数据域

| 数据域 | 最低字段 | 支持能力 | 不足时的处理 |
|---|---|---|---|
| 证券历史身份 | 稳定证券 ID、代码与交易所、有效起止、上市/退市、ST/*ST、交易板块 | 股票池与历史状态 | 身份或 ST 状态不明的标的不发布有效候选 |
| 交易日历与规则 | 日期、时区、交易阶段、停市、逐股票限价及适用规则 | 窗口、观察期、限制 | 不按自然日加天数；规则不明标记 |
| 历史日线 | 原始 OHLC、有效参考前收盘、额量、停牌标记、修订号 | 趋势、波动、基线 | 因子逐项检查最低历史 |
| 公司行为 | 除权除息、生效日期、公告时间、调整依据及版本 | 价格可比及评价 | 不把除权价差当作收益或突破 |
| 当前行情 | 事件时间、最新价、截至当时高低价、累计额量、前收盘参考、交易状态 | 尾盘筛选 | 缺实时能力不能以盘后补数替代 |
| 历史/当前分钟 | 起止时间、完成标记、OHLC、成交股数/额、交易阶段 | 同刻量比、尾盘强度、参考价格 | 最新快照不能恢复缺失分钟路径 |
| 指数/市场序列 | 指数身份、同期价格、日线/分钟、构造说明 | 市场状态与对照 | 采用已批准且覆盖充分的比较序列 |
| 行业及概念成员 | 分类身份、成员证券、有效起止、当时可知时间 | 板块轮动与历史归属 | 当前成员不能冒充历史成员 |
| 资金方向 | 净额或买卖额、统计区间、分类规则、来源及可用时间 | F03–F06 | 不同口径不可拼接；仅盘后数据作历史背景 |
| 政策与事件 | 原文/链接、主体、发布时间、获取时间、修订、结构化对象 | P01–P07、R07 | 缺历史只做前向积累；未覆盖不能当无事件 |
| 可选盘口 | 买卖价格与数量、时间、最小价位 | 流动性与成交不确定性 | 无盘口不输出零价差或确定可成交结论 |

单位标准：金额为人民币元，成交量为股，价格为元/股；存储收益率使用小数，UI 再转百分数；时间保留带时区的完整时间戳。API 的“手”“万元”“百分数”必须显式转换。

资金口径还应包含：主动方向识别方法、大小单阈值、按委托或成交分类、是否含中性成交、是否盘后重算。无文档时只能标注未知，不能自造定义。

## 3. 时间、历史与修订

建议标准记录包含：

| 字段 | 意义 |
|---|---|
| event_time / bar_start / bar_end | 市场事件或统计区间的时间 |
| published_at | 来源首次公开时间，未知时保留未知 |
| source_available_at | API 允许取得该记录的时间，如可核实 |
| received_at | 本系统实际收到的时间 |
| valid_from / valid_to | 状态或成分事实的生效区间 |
| revision_id / source_version | 修订及口径版本 |
| decision_cutoff | 当次筛选允许使用信息的最晚时点 |
| signal_published_at | 用户实际能够看到结果的时间 |

实时运行：数据事件时间不晚于截点，系统实际获取时间也不晚于截点；已完成分钟必须同时满足 bar_end 与收到时间约束。计算和发布可以晚于截点，但延迟需显示并进入参考价格设定。

历史研究分三种证据等级：

1. **真实快照回放**：有当时收到的数据和发布记录，按实际可用时间回放。
2. **有依据的历史仿真**：有来源发布日期、历史版本及可核实的发布机制，按事先确定的延迟假设重建；明确标为仿真。
3. **时点不可验证研究**：只有今天下载的最终历史数据或当前事件解释，无法证明当时可得；仅作探索，不能充当严格尾盘样本外验证。

今天下载历史数据的 received_at 是今天，不能伪造成当时接收到的时间；也不应因为今天才下载而把所有可核实的历史数据都一概视为未来信息。通过上述证据等级和源可用时间区分。

政策事件公开于 14:20、系统 14:42 才收到时，实时 14:30 信号不能使用它。供应商 15:30 才生成的当日资金统计，不能用于当天任何尾盘信号，即使返回字段的 trade_date 是当天。

更正只产生新数据版本。原发布仍保留原输入；另行计算“使用修订数据后的研究结果”，两者不得混为同一历史业绩。

## 4. 缺失与降级决策

| 情形 | 行为 |
|---|---|
| 核心行情过期、市场覆盖严重不足 | 阻断新的有效名单，展示状态；保留旧快照但标记过期 |
| 单股报价或 ST 状态不明 | 该股无法通过当前筛选，不改变其他有效股票 |
| 某个交易板块整体无数据 | 明示范围缺口；全市场正式模式不视为完成 |
| 必需历史长度不足 | 标为历史不足，该策略不评分；研究池仍保留该股 |
| 同刻历史分钟缺失 | 相关同刻因子不可用；不拿全天数替代 |
| 资金增强源不可用 | 仅能切换到预先批准的基础配置，并展示版本变化；无此配置则停止增强方案 |
| 事件源未覆盖 | 展示未覆盖；事件必需方案不可用，非事件方案可按其声明运行 |
| 来源字段为零 | 先判断是真零、停牌、缺失哨兵还是单位错误 |
| 来源修订/定义变更 | 暂停混用受影响序列，保留原批次，重新核验 |

不能逐股删掉缺失因子后自动归一化权重，再声称是同一个策略。降级策略需要自己的数据依赖、评价结果和批准记录。

## 5. 信号样本与参考价格

### 5.1 样本锁定

建议主评价以每天 14:50 的有效发布快照为准，14:30/35/40/45 的快照分别作辅助时点评价。该选择仅用于统一研究，不宣称 14:50 最优。

主样本键为 `(trade_date, security_id, strategy_version, evaluation_policy_version)`。同日同股在多个时间点出现，不重复充当主样本。多策略同时命中的股票在整体名单评价只记一次，分策略研究保留触发关系。

若用户更重视首次出现即决策，可以另设“首次有效入选”评价组，并把其时点规则提前锁定。不能在看到后续收益后从五次名单中挑最好的一次。

14:50 轮没有有效发布：记录该日数据失败或任务失败，不自动用 14:45 代替。有效运行但无候选：记录零候选日。两者都进入使用覆盖统计，但不凭空生成收益样本。

同股连续多日入选可以作为不同日期的信号，但标记连续事件簇；统计时考虑相关性，不能把它们视为完全独立试验。

### 5.2 参考入场价格建议

为避免使用发布前价格和无法解释的瞬时价格，提出以下可复现研究初值：

1. 从实际 signal_published_at 起加入 60 秒固定观察/反应延迟。
2. 取该时刻之后开始的第一个完整 1 分钟区间，参考价格为该区间成交额 / 成交股数。
3. 区间必须处于连续竞价阶段、数据完整且有成交；不跨到收盘集合竞价或下一日补价。
4. 无有效区间、处于明显受限交易状态，或无法合理检查参考可执行性，记为 `ENTRY_UNCERTAIN`，不假设成交。

例：14:45:20 发布，加延迟到 14:46:20，参考区间为 14:47:00–14:48:00。分钟时间戳究竟代表起点还是终点，必须由适配器明确转换。

这个价格只是信号比较基准，不是建议买入时间，也不证明用户能以该价格成交。末次发布的参考区间可能位于 14:50 之后；它用于保守评价，不扩大已约定的使用窗口。正式取价和延迟需要在 API 可用性核验后批准。

同时研究 30/120 秒延迟及保守滑点敏感性，不能从中事后选最优值作为正式结果。当前只有日线时无法实现该主评价，不用次日开盘结果冒称同一种尾盘策略。

## 6. 1 / 3 / 5 日标签

### 6.1 时间与收益

信号日为 D，主终点为 D+3 的收盘，第 D+1 和 D+5 收盘为辅助。以交易日历推进，信号日不计为第 1 日。

无公司行为时：`R_h_gross = Close(D+h)/P_ref − 1`。

有公司行为时，从参考时点的一股持有量开始，按实际发生的拆并股、分红等更新数量 q_h 与现金 cash_h：`R_h_gross = (q_h*Close(D+h)+cash_h)/P_ref−1`。涉及配股等需额外选择的事项，采用预先定义的处理规则；无法重建时标记评价未解决，不能把数据差异视为亏损或盈利。

同时保留粗略统一摩擦假设：`R_h_net = R_h_gross − c`。c 为一次进入及退出的总参考成本，包括所声明的费用与滑点假设；这是近似研究口径，不是实际订单费用模型。

研究起点可设 c=30 个基点（0.30%），同时报告 0、10、60 个基点结果。这些是敏感性场景，不是当前法定税率、券商费率或用户真实成本。实际账户结果不进入本计算。

### 6.2 主要指标

- 3 日胜率：评价充分且满足参考可执行性条件的信号中，`R_3_net>0` 的比例；等于零不算胜。
- 平均/中位数参考净收益，平均正收益与平均负收益绝对值，尾部损失。
- 最大不利波动：从参考时点到 D+3 的经济价值最低变动；按实际可得分钟或日线粒度标记精度。D 日不能使用参考时点之前已经发生的最低价。
- 同时报告从 D+1 起可卖出阶段的不利波动，避免暗示信号日新买入后能当日止损。
- 相对市场和行业的同期间收益差，使用同一时间基点和事先确定的基准；不称为已估计因子模型 Alpha。
- 日均候选数、非空日比例、市场/板块覆盖、信号可评价率、参考受限比例。
- 1 日用于及时性与短期走弱观察，5 日用于持续性，不自动用辅助期最好的结果替代 3 日目标。

不将信号平均收益简单年化，不把重叠信号累加成账户净值或最大回撤。未定义实际持仓与资金约束时，不报告账户级 Sharpe。

### 6.3 停牌、交易约束与缺失不得被删除

| 状态 | 处理 |
|---|---|
| `PENDING` | 观察期未结束，不进入成熟样本胜率 |
| `EVALUATED` | 参考入场与终点评价资料充分，产生收益和成功标签 |
| `ENTRY_UNCERTAIN` | 入场参考受限，保留已选信号，不假设买入成功 |
| `EXIT_CONSTRAINED` | 到期停牌、明显卖出受限等；保留估值结果，但不当作已实现退出收益 |
| `DATA_UNRESOLVED` | 价格、公司行为或时间语义缺失；等待核验且保留样本 |
| 退市或其他终止事件 | 继续跟踪可核实结果；无法估值时保留未解决状态，不能从历史池删除 |

对所有已成熟信号 N，报告：已确定成功 W、已确定失败 L、尚未解决/受限 U，其中 N=W+L+U。确定样本胜率为 W/(W+L)，同时给出全体成熟样本的保守上下界 `[W/N,(W+U)/N]`。这是对未知结果的边界，不是实际成交胜率。

资料不足时不能只展示确定样本中漂亮的胜率。升级比较同时检查 U/N；不同方案缺失率差异大时，无法据胜率认定改进。

暂停交易导致 D+3 没有正常价格时，不能顺延到复牌日仍叫 3 日结果。可以另外记录“恢复交易后的结果”，与原终点分开。

## 7. 因子与策略验证

### 7.1 数据与计算正确性

先验证单位、代码、除权、时区、分钟边界、缺失与重复，以及当时可得性。关键情形包括：跨板块规则差异、ST 状态变化、新股、停牌、盘中临停、价格限制、源迟到、板块成分变化、事件修订。

手工复算少量因子实例与边界情形，确认原值、标准化和原因一致。策略研究不得用这些已用于调试的实例反复挑选展示成效果证据。

### 7.2 单因子研究

每个因子先验证：覆盖、稳定性、极端值、与同组因子的相关性；然后检查它与未来 3 日标签的关系。

- 分位分组的收益、成功率与不利波动；检查是否单调或只在某个区间有效。
- Rank IC 可作排序诊断，但须连同每天的样本量、板块与规模暴露报告。
- 在不同市场状态及板块分别观察，不从样本很少的分组中宣称规律。
- 以同日、同股票范围和风险资格的对照比较；覆盖少的增强因子同时报告共同覆盖样本与全产品效果。

事件因子还要评估来源真实性、映射准确度、时延、重复事件和标注一致性。历史上用今天的模型重读新闻的结果，只能视为特定模型的历史仿真，不能冒充当时人工或系统已经知道的判断。

### 7.3 多因子与样本外

按时间划分训练、验证与保留测试；采用滚动前向验证。训练标签必须在训练截止时已经完全成熟。若研究同时观察到 5 日辅助标签，分割处清除跨越边界的样本，不能简单随机打散。

标准化、阈值、行业映射学习、模型训练及参数搜索均在允许的训练/验证范围内完成。保留测试不能在每次失败后重复调参使用；一旦用于决策，视为已消耗的验证数据，下一轮需要新的未见数据或前向观察。

不把今天的股票池、行业成分、修订后的事件及 HMM 全样本状态回填过去。若以后试用 HMM，只使用截至各截点的训练与过滤状态，不能使用未来观测平滑出的状态作为当时已知输入。

### 7.4 必需对照

| 对照 | 检验的问题 |
|---|---|
| 同样资格下的简单相对动量 BM | 复杂方法是否优于简单基线 |
| 同日可用池的匹配随机候选 | 优势是否主要来自行情、板块和规模暴露 |
| 去掉某因子组 | 板块、资金、政策、市场状态分别贡献多少 |
| 固定规则与自适应规则 | 环境切换是否增加价值 |
| 有无名单稳定性/关联约束 | 实用性改善是否牺牲效果，风险是否减少 |
| 同一策略不同发布时点 | 时点效果与延迟敏感性；不事后挑最佳 |

### 7.5 不确定性与试验数量

按交易日整体保留当日候选，并用连续日期块评估不确定性，以保留同日相关与跨日标签重叠；块长度至少覆盖最大观察周期，并做长度敏感性。板块集中和同股重复需要另外归因。

研究必须报告交易日数、信号数、同股连续簇、行业覆盖及行情覆盖，不能用“5 只×20 天=100 次独立试验”的说法。

所有参数尝试、失败方案及筛选规则写入实验登记。候选因子多、数据有限时，优先减少同时搜索的参数；不通过反复增加组合直到找到高胜率。

不设置“满某个固定信号数就证明有效”的自动规则。新方案胜率的点估计提高但区间很宽，结论应是继续观察，而不是宣布改善已成立。

## 8. 迭代提案的评审门槛

进入用户确认前，系统应已准备可审阅证据：

1. 数据能力与时间语义符合方案依赖，无已知未来信息。
2. 所有指标基于固定评价版本，3 日为主，1/5 日辅助。
3. 与旧版在相同日期和共同样本的效果比较，以及整体覆盖差异。
4. 样本外与前向证据、收益风险权衡、成本及时间敏感性。
5. 明确哪些行情未观察到，哪些事件数据不完整。
6. 变更列表、启用日期、旧版本及恢复方式。

不以某个未经约定的绝对胜率作为通过条件；数据与样本不足时提案可以建议继续观察。用户确认改变正式配置，不改变历史发布。

## 9. 框架验收条件

以下是未来验证框架的检查标准，不是开发任务排期：

- 任一历史候选可以还原数据批次、因子、规则、事件原文和当时状态。
- 14:45 的计算不读取当日收盘价、盘后资金结果或之后才获取的新闻。
- 缺失和零值不同，API 源更换会显式影响版本。
- 全部非 ST 市场的覆盖可以分板块显示；不会在失去某一板块数据后仍宣称全覆盖。
- 候选最多 5 只，允许 0 只，数据失败与无机会有明确区别。
- 同日重复发布不膨胀主样本；无法成交、停牌和退市样本不被删除。
- 3 日评价按交易日历，1/5 日分列；信号结果不冒充实际账户收益。
- 每次正式规则变化有确认和未来生效时间；能够恢复此前版本。
- 页面显示真实行情时间和发布时间；任务重试不会重复发布或重复计样本。
- 备份恢复后仍能保留数据版本、提案确认和信号证据链。

## 10. Fuyao API 接入时需核对的资料

用户已提供 Fuyao API，本阶段已完成文档阅读和少量只读响应核验；详细映射见[Fuyao API 映射与能力评估](04-fuyao-api-mapping.md)。正式接入前仍需核对：接口文档或示例响应、鉴权方式、市场覆盖、时间戳语义、单位、刷新和延迟、历史范围、修订机制、限频及断线恢复、使用范围。

尤其需要区分：

- 历史分钟与实时分钟是否是独立能力。
- 行业/概念接口是否有历史成员，而非只有今天的列表。
- 资金流是否当时可得、是否盘后重算、是否覆盖北交所。
- 政策事件是否有首次发布时间、历史修订和原文链接。
- 当日高低价、累计额量是否包含相同交易阶段。

供应商适配只负责标准化，不在适配层暗中改变因子公式或筛选规则。
